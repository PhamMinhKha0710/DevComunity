## Session 2: Thiết Kế Lại Hệ Thống Like & View

**Nhánh làm việc:** `feature/frontend-redesign-v2` (đã merge từ `fix/frontend-ui-fixes` + `feature/like-view-system-redesign`)
**Build status:** PASSED (0 errors, 0 warnings)

### Mục tiêu

Redesign hệ thống Like và View sử dụng Redis cho realtime counters, MongoDB cho activity logs, RabbitMQ cho async notifications, và SignalR cho realtime push -- tận dụng toàn bộ infrastructure đã có sẵn.

### Vấn đề cũ

1. **Votes**: lưu SQL `Votes` table, score tính bằng `SELECT + SUM` mỗi lần (N+1 trên list pages)
2. **Views**: `UPDATE SET ViewCount = ViewCount + 1` trực tiếp trên SQL mỗi page load
3. **Like notification**: chỉ lưu SQL, không push realtime qua SignalR
4. **Không có activity logging**: không có MongoDB logs cho likes/views
5. **Notification trùng lặp**: `VoteNotificationHandler` (domain event) + `LikeNotificationConsumer` (RabbitMQ) tạo 2 notification

### 6 Phase Đã Hoàn Thành

#### Phase 1: Redis Like Counter + Cache
- `RedisLikeService` với keys `like:{type}:{id}:count` (INCR/DECR) + `like:{type}:{id}:users` (SADD/SREM/SISMEMBER)
- Batch read `GetLikeCountsBatchAsync` dùng `StringGetAsync(RedisKey[])` thay vì N+1 SQL
- `VoteCommandHandlers` ghi Redis sau SQL, trả Redis-based scores
- 4 query handlers (`GetQuestions`, `GetQuestionById`, `Answers`, `UserContent`) đọc batch từ Redis, fallback SQL

#### Phase 2: Redis View Counter + Batch Sync
- `RedisViewService` với HyperLogLog cho unique visitors + INCR cho totals
- `ViewSyncBackgroundService` (IHostedService) chạy mỗi 60s, đọc delta keys `view:question:*:delta` và batch update SQL
- `QuestionsController.GetQuestion` dùng Redis INCR thay vì MediatR command

#### Phase 3: MongoDB Activity Logs
- `ActivityLogService` với collections `post_likes` (compound unique index) + `post_views` (descending date index)
- Fire-and-forget logging từ command handlers và QuestionsController
- Upsert cho likes, insert cho views

#### Phase 4: RabbitMQ Event Bus
- `SocialEventPublisher` dùng exchange `social.events` (topic), routing keys `like.question`/`like.answer`
- `LikeNotificationConsumer` (IHostedService) consume queue `social.events.likes`, tạo SQL notification + delegate SignalR push
- `ILikeNotificationHandler` interface để tách SignalR dependency khỏi Infrastructure layer

#### Phase 5: SignalR Realtime Push
- `SignalRLikeNotificationHandler` (API layer) push `ReceiveNotification` tới content author qua `NotificationHub`
- Broadcast `VoteChanged` tới question room qua `QuestionHub`
- Xóa `VoteNotificationHandler` cũ (tránh notification trùng lặp)

#### Phase 6: Frontend Realtime + UI
- `useHub("question")` subscribe `VoteChanged` event, update React Query cache
- `JoinQuestion`/`LeaveQuestion` SignalR groups on mount/unmount
- Nút "Phản hồi" trên answers: toggle reply form, hiển thị comments thread, gọi `POST /api/comments/answer/{id}`
- `commentsApi` client mới
- Right sidebar sticky (`sticky top-0 self-start max-h-[calc(100vh-6rem)] overflow-y-auto`)

### Mục tiêu

Tối ưu database architecture để chuẩn bị scale lên 10M users. Dựa trên bản phân tích kiến trúc dữ liệu (Plan: `database_architecture_analysis_a65939c7`). Tập trung vào: composite indexes, full-text search, loại bỏ Redis SCAN, batch SQL updates, distributed cache, MongoDB TTL cleanup, RabbitMQ reliability.

### Nhánh 1: optimize/composite-indexes-fulltext

#### SQL Server Composite Indexes

| Entity | Trước | Sau |
|--------|-------|-----|
| Notification | 3 index đơn: `UserId`, `IsRead`, `CreatedDate` | Composite `(UserId, IsRead, CreatedDate DESC)` + `(UserId, CreatedDate DESC)` |
| Vote | Filtered index KHÔNG unique | Thêm `.IsUnique()` chống duplicate vote tại DB level |
| Question | 5 index đơn | Thêm composite `(UserId, CreatedDate DESC)` cho profile page, `.IsDescending()` cho Score/CreatedDate |
| Answer | 3 index đơn: `QuestionId`, `IsAccepted`, `Score` | Composite `(QuestionId, Score DESC)` + `(QuestionId, IsAccepted)` |
| Post | 3 index đơn: `CreatedAt`, `AuthorId`, `GroupId` | Composite `(AuthorId, CreatedAt DESC)` + `(GroupId, CreatedAt DESC)` |

#### Full-Text Search

### Nhánh 2: optimize/redis-scaling-fixes

#### Loại bỏ SCAN/KeysAsync (O(N) → O(1))

| Service | Trước (SCAN) | Sau (Tracking Set) |
|---------|-------------|-------------------|
| `RedisViewService` | `server.KeysAsync("view:question:*:delta")` | `SMEMBERS view:delta:tracking` + `SADD` khi increment |
| `RedisPresenceService` | `server.KeysAsync("presence:user:*")` | `SMEMBERS presence:online` + `SADD`/`SREM` on connect/disconnect |

#### ViewSync Batch Update

| Trước | Sau |
|-------|-----|
| N lần `IncrementViewCountAsync(+1)` trong loop | 1 lần `IncrementViewCountByDeltaAsync(id, delta)` per question |
| O(N) SQL roundtrips | O(1) SQL UPDATE per question |

#### Distributed CacheService (L1 + L2)

| Trước | Sau |
|-------|-----|
| `IMemoryCache` only (single instance) | Redis L2 + `IMemoryCache` L1 (30s local TTL) |
| Không hoạt động multi-instance | Chia sẻ cache giữa multiple app instances |
| DI: `AddSingleton<ICacheService, CacheService>()` | DI: factory injection, truyền `IConnectionMultiplexer?` |

#### Like Counter TTL

- Thêm `CounterTtl = 1 day` cho like count + user set keys
- Thêm `CounterTtl = 7 days` cho view count keys
- Keys tự hết hạn, tái tạo từ SQL khi cần (lazy reload)

### Nhánh 3: optimize/mongodb-ttl-cleanup

| Collection | TTL | Mục đích |
|------------|-----|----------|
| `post_views` | 90 ngày (`CreatedAt`) | Xóa view logs cũ, giảm storage |
| `outbox` | 7 ngày (`ProcessedAt`) | Xóa events đã xử lý, `ProcessedAt=null` được bỏ qua |

#### Outbox Indexes

| Index | Mục đích |
|-------|----------|
| `(Processed, CreatedAt)` | Tăng tốc query pending events |
| `TTL_Outbox_Processed_7d` | Auto-cleanup sau 7 ngày |

#### UserInfoEmbed Staleness Fix

| Thay đổi | Trước | Sau |
|----------|-------|-----|
| `RedisChatCacheService.UserInfoTtl` | 30 phút | 5 phút |
| `RedisChatCacheService` | Không có invalidation | Thêm `InvalidateUserInfoAsync(userId)` |
| `UpdateProfileCommandHandler` | Không invalidate cache | Gọi `_cacheService.RemoveByPrefix("user:{id}")` khi update |

### Nhánh 4: optimize/rabbitmq-reliability

#### LikeNotificationConsumer Upgrade

| Feature | Trước | Sau |
|---------|-------|-----|
| Dead Letter Queue | Không có | `social.events.likes.dlq` + `x-dead-letter-exchange/routing-key` args |
| Queue Recreation | Không có | Self-healing khi `PRECONDITION_FAILED` (recreate với DLQ args) |
| Idempotency | Không có | Redis key `like:evt:processed:{eventId}` (TTL 24h) |
| Retry Logic | Requeue vô hạn | Max 3 retries via `x-death` header count, sau đó → DLQ |
| Prefetch | Mặc định (unlimited) | `BasicQos(prefetchCount: 10)` |
| Graceful Shutdown | `stoppingToken.Register` | Override `StopAsync()` đóng channel properly |

#### LikeEvent Enhancement

| Thay đổi | Mục đích |
|----------|----------|
| Thêm `EventId = Guid.NewGuid().ToString()` | Unique identifier cho idempotency |
| `SocialEventPublisher`: thêm `MessageId = evt.EventId` | RabbitMQ message ID header |
