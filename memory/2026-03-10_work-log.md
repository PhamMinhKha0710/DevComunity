## Phase 2: Tích hợp Redis Cache + RabbitMQ Message Broker

**Thời gian thực hiện:** ~15:30 - 17:00

### Mục tiêu

Tăng tốc độ và hiệu suất hệ thống chat bằng:
- **Redis**: Cache data, fast ID generation, unread counts
- **RabbitMQ**: Async event processing (notifications, analytics)

### Kiến trúc tổng thể sau tích hợp

```
Frontend (Next.js / SignalR)
    |
    v
ChatHub (SignalR) ─── publish events ───> RabbitMQ Exchange
    |                                         |
    v                                         v
IChatRepository                    ChatMessageConsumerService
    |                              (BackgroundService)
    v                                    |
MongoChatRepository ─── cache ──> Redis  |
    |                                    v
    v                              - Create notifications
MongoDB                            - Analytics processing
```

### Redis - Chi tiết tích hợp

| Chức năng | Key Pattern | Hiệu quả |
|-----------|-------------|-----------|
| Fast ID generation | `chat:seq:{name}` | Redis INCR ~1ms vs MongoDB counter ~5-20ms |
| Cache conversation | `chat:conv:{id}` | Redis GET ~1ms vs MongoDB Find ~5ms (TTL 10 phút) |
| Cache user info | `chat:user:{userId}` | Redis GET ~1ms vs SQL Server query ~10ms (TTL 30 phút) |
| Unread counts | `chat:unread:{userId}:{convId}` | Redis INCR/GET ~1ms (atomic counter) |
| Sequence sync | `chat:seq:{name}` | Đồng bộ sequence từ MongoDB khi khởi động |

**Tác động hiệu suất:**
- `GetConversationByIdAsync`: ~5ms → ~1ms (cache hit)
- `AddMessageAsync` ID generation: ~15ms → ~1ms (Redis INCR)
- `GetUserInfoAsync` (mỗi lần gửi tin nhắn): ~10ms → ~1ms (cache hit)
- **Tổng giảm latency mỗi message: ~25-30ms**

### RabbitMQ - Chi tiết tích hợp

| Component | Mô tả |
|-----------|--------|
| Exchange | `chat.events` (topic exchange, durable) |
| Queue | `chat.events.process` (durable, prefetch=10) |
| Routing keys | `message.#`, `reaction.#` |
| Publisher | `RabbitMqChatMessageBroker` (singleton) |
| Consumer | `ChatMessageConsumerService` (BackgroundService) |

**Event types:**
- `message.new` → Tạo notification cho participants (async, không block ChatHub)
- `message.read` → Log analytics (async)
- `reaction.add` / `reaction.remove` → Log analytics (async)

**Fire-and-forget pattern:** ChatHub publish events sau khi broadcast. Nếu RabbitMQ unavailable, gracefully degrade (log warning, không crash).

### Graceful degradation

Hệ thống tự động xử lý khi service unavailable:
- **Redis off** → MongoChatRepository fallback về MongoDB counter + SQL Server user lookup
- **RabbitMQ off** → ChatHub skip publish, log warning (chat vẫn hoạt động bình thường)
- **MongoDB off** → Fallback về SQL Server ChatRepository (nếu xóa MongoDB config)

### Phase 2: MediatR Migration + ChatHub Refactor (4 tasks - COMPLETED)

**Đây là thay đổi lớn nhất trong ngày.**

#### 2a. Convert ~50 handlers sang MediatR IRequestHandler (COMPLETED)

Biến đổi pattern cho TẤT CẢ handlers:

```
Before: public class XxxHandler { public async Task<T> HandleAsync(XxxCommand cmd, CancellationToken ct) }
After:  public class XxxHandler : IRequestHandler<XxxCommand, T> { public async Task<T> Handle(XxxCommand request, CancellationToken ct) }
```

**Domains đã chuyển đổi:**
- Auth (6 handlers): Login, Register, Logout, RefreshToken, ForgotPassword, ResetPassword
- Questions (5): Create, Update, Delete + GetQuestions, GetQuestionById
- Answers (4): Create, Update, Delete, Accept + queries
- Comments (3): Create, Update, Delete
- Votes (2): Vote, Unvote
- Chat (5): StartConversation, SendMessage, MarkRead, AddReaction, RemoveReaction + queries
- Notifications (2): MarkRead, MarkAllRead + query
- SavedItems (2): Save, Unsave + query
- Repositories (3): Create, Update, Delete + queries
- Users, Tags, Badges, Search: query handlers

**Thay đổi đặc biệt:**
- Tạo mới query classes cho handlers nhận primitive params (ví dụ: `GetUserQuestionsQuery { UserId, Page }`)
- Tạo `SavedItemsResponse` class thay tuple `(IEnumerable, int)` (MediatR không hỗ trợ tuple)
- Tạo `LogoutCommand { UserId }`, `UpdateProfileCommand { UserId }` cho handlers nhận int

#### 2b. Update 18 controllers sang IMediator (COMPLETED)

**Pattern cho mỗi controller:**

```
Before: constructor nhận 5-8 concrete handlers
After:  constructor nhận IMediator + ILogger (+ domain-specific services nếu cần)
```

**Controllers đã chuyển:** Auth, Chat, Questions, Answers, Comments, Votes, Notifications, SavedItems, Users, Tags, Badges, Search, Repositories

**Controllers giữ nguyên (chỉ dùng repositories):** Groups, Friendship, Follow, Newsfeed, Media

#### 2c. Clean up DependencyInjection.cs (COMPLETED)

Xóa ~60 dòng `services.AddScoped<XxxHandler>()` thủ công. MediatR `RegisterServicesFromAssembly` tự scan.

**Kết quả:**
```csharp
// Trước: 70+ dòng
// Sau: 12 dòng
services.AddMediatR(cfg => {
    cfg.RegisterServicesFromAssembly(typeof(DependencyInjection).Assembly);
    cfg.AddBehavior(typeof(IPipelineBehavior<,>), typeof(LoggingBehavior<,>));
});
```
