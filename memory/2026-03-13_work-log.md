## Session 1: Realtime Architecture Improvements

### Task 1: Wire ActivityHub vào newsfeed (P1)

**Files:** `frontend/src/lib/signalr/connectionManager.ts`, `frontend/src/app/(app)/newsfeed/page.tsx`  

**Ý chính:**

- Thêm `'activity'` vào `HubName`, dùng chung connection manager.

- Newsfeed subscribe `NewPost` / `NewGroupPost` / `NewQuestion` từ `ActivityHub`, khi nhận event sẽ invalidates `['newsfeed']` để refetch.

### Task 2: Scope PresenceHub theo bạn bè (P1)

**Files:** `RedisPresenceService.cs`, `PresenceHub.cs`, `IFriendshipRepository.cs`, `chat/page.tsx`  

**Ý chính:**

- RedisPresenceService thêm cache bạn bè + API `GetOnlineFriendsAsync`, `FilterOnlineAsync`, đánh dấu `GetOnlineUserIdsAsync` là `[Obsolete]`.

- PresenceHub:

  - OnConnected: join `user_{userId}`, cache bạn bè, join các group `friends_of_{friendId}` cho từng friend.

  - Online/offline chỉ broadcast tới `friends_of_{userId}` thay vì `Clients.Others`.

  - Thêm `GetOnlineFriends()` và `GetOnlineInConversation(conversationId)`.

- Frontend chat đổi `GetOnlineUsers` → `GetOnlineFriends`.

### Task 3: Chat push qua RabbitMQ consumer (P2)

**Files:** `IChatPushHandler.cs`, `SignalRChatPushHandler.cs`, `ChatMessageConsumerService.cs`, `Program.cs`  

**Ý chính:**

- Tạo `IChatPushHandler` + `ChatPushEvent` ở Application.

- `SignalRChatPushHandler` dùng `IHubContext<ChatHub>` để push `ReceiveMessageNewMessageNotification`.

- `ChatMessageConsumerService.HandleNewMessageAsync`:

  - Vẫn tạo SQL `Notification` như cũ.

  - Gọi `IChatPushHandler.PushNewMessageNotificationAsync` → đường đi **MongoDB → RabbitMQ → consumer → SignalR** (có idempotency, retry, DLQ).

- Đăng ký DI: `IChatPushHandler` → `SignalRChatPushHandler`.

### Task 4: Reconnect sync cho chat hub (P2)

**Files:** `connectionManager.ts`, `useHub.ts`, `chat/page.tsx`  

**Ý chính:**

- `connectionManager.ts`: thêm `reconnectCallbacks`, `onReconnected` / `offReconnected`, gọi callback khi `connection.onreconnected`.

- `useHub.ts`: expose `onReconnected` / `offReconnected`.

- `chat/page.tsx`: khi chat hub reconnected:

  - Lấy conv đang mở `selectedConvRef`), `lastMessageId` hiện tại.

  - Gọi `SyncMessages(conversationId, lastMessageId)` để lấy delta messages.

  - Gọi lại `fetchConversations()`.

### Task 5: Redis `pending_push` cho user offline (P3)

**Files:** `RedisPresenceService.cs`, `ChatMessageConsumerService.cs`, `PresenceHub.cs`, `chat/page.tsx`  

**Ý chính:**

- RedisPresenceService:

  - Thêm TTL friends cache (10’) + pending push (7 ngày).

  - API: `AddPendingPushAsync`, `DrainPendingPushAsync`, `GetPendingPushCountAsync`.

- ChatMessageConsumerService:

  - Nếu recipient offline `IsOnlineAsync == false`) → ghi payload `{ type: "chat_message", conversationId, messageId, senderUsername }` vào `presence:pending_push:{userId}`.

- PresenceHub:

  - Khi user từ offline → online: ngoài `UserOnline` còn `DrainPendingPushAsync` và gửi event `PendingNotifications` cho `Clients.Caller`.

- Chat frontend: lắng nghe `PendingNotifications` và `fetchConversations()` lại (có thể sau này hiển thị badge số lượng).

### Task 6: Thay `GetOnlineUsers` bằng API scoped (P3)

**Files:** `PresenceHub.cs`, `RedisPresenceService.cs`, `chat/page.tsx`  

**Ý chính:**

- Giữ `GetOnlineUsers()` chỉ để backward compat + `[Obsolete]`.

- Frontend chuyển hết sang:

  - `GetOnlineFriends()` cho màn chat.

  - Có sẵn `GetOnlineInConversation(conversationId)` cho future use.

- Đã grep: không còn caller `GetOnlineUsers` ở frontend.
